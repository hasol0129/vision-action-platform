0준비물 확인

이 프로젝트는 Docker 컨테이너 5개(django · fastapi · celery · redis · postgres)로 돌아갑니다. 파이썬·DB를 PC에 따로 설치할 필요는 없습니다.

필요한 것확인 방법
WSL2 + UbuntuWindows wsl -l -v → Ubuntu의 VERSION이 2
Docker Desktop (실행 중)작업표시줄 고래 아이콘이 켜져 있음
Docker를 WSL에서 쓰도록 연결Docker Desktop → Settings → Resources → WSL integration → Ubuntu 켜기 → Apply
디스크 여유 10GB 이상AI 라이브러리(PyTorch 등) 이미지가 큽니다
(IP Webcam을 쓸 때) 휴대폰 카메라 앱DroidCam(포트 4747) 또는 IP Webcam(포트 8080), PC와 같은 와이파이
1
Ubuntu 터미널에서 Docker가 보이는지 확인합니다. 
docker version --format "{{.Server.Version}}"
docker compose version
숫자 버전이 나오면 준비 완료입니다. docker: command not found가 나오면 위 표의 WSL integration을 켜고 터미널을 다시 여세요.

1zip 압축 풀기

Windows 폴더(/mnt/d/...)에서 바로 실행해도 되지만, WSL 안(홈 폴더)에 풀면 빌드와 파일 읽기가 훨씬 빠릅니다.

1
WSL zip을 WSL 홈으로 복사하고 압축을 풉니다. (zip이 다른 곳에 있으면 경로만 바꾸세요) 
mkdir -p ~/vap && cd ~/vap
cp "/mnt/d/dev2/hasol/교과 10 자세추정/10일 수업/교과10 최종프로젝트/vision_action_platform_final.zip" .
unzip -q vision_action_platform_final.zip
cd vision_action_platform
ls
CODE_GUIDE.md README.md ai_service backend compose.yaml docs 이 보이면 성공입니다.
이 PC에 이미 돌아가고 있는 프로젝트가 있다면 같은 이름의 컨테이너·DB를 같이 쓰게 되어 꼬일 수 있습니다. 2단계에서 COMPOSE_PROJECT_NAME을 다른 이름(예: vap_zip)으로 바꾸고, 기존 것은 먼저 끄세요: 기존 폴더에서 docker compose down (데이터는 남습니다).

unzip이 없다고 나오면: sudo apt install -y unzip

2설정 파일(.env) 만들기

비밀번호·포트·카메라 주소는 코드가 아니라 .env에 둡니다. .env는 Git과 zip에 들어가지 않습니다.

1
WSL 예시 파일을 복사합니다. 
cp .env.example .env
2
WSL 비밀키와 DB 비밀번호를 무작위 값으로 채웁니다. (그대로 복사해 실행) 
SECRET=$(python3 -c "import secrets; print(secrets.token_urlsafe(48))")
DBPASS=$(python3 -c "import secrets; print(secrets.token_urlsafe(18))")
sed -i "s|^DJANGO_SECRET_KEY=.*|DJANGO_SECRET_KEY=$SECRET|; s|^POSTGRES_PASSWORD=.*|POSTGRES_PASSWORD=$DBPASS|" .env
grep -c change-me .env   # 0 이 나오면 OK
3
필요하면 나머지 값을 고칩니다: nano .env (저장: Ctrl+O → Enter, 나가기: Ctrl+X)
변수기본값언제 바꾸나
DJANGO_PORT80008000번을 다른 프로그램이 쓰면(접속이 안 되면) 8010 등으로. 바꾸면 바로 위 DJANGO_CSRF_TRUSTED_ORIGINS의 포트도 같이 변경
FASTAPI_PORT80018001이 이미 쓰이고 있을 때
ALLOWED_CAMERA_URLS예시 주소휴대폰 카메라 주소. DroidCam: phone1=http://<폰IP>:4747/video · IP Webcam: phone1=http://<폰IP>:8080/video
CAMERA_ROTATE0카메라 영상이 옆으로 누워 보이면 90 (반대로 누우면 270)
CAMERA_CAPTURE_SECONDS8IP Webcam 수집 시간(초)
UNCERTAIN_THRESHOLD0.4이 값보다 신뢰도가 낮으면 "판단 불확실" 표시
COMPOSE_PROJECT_NAMEvision_action_platform같은 PC에서 두 벌을 띄울 때만 다른 이름

휴대폰 IP는 DroidCam·IP Webcam 앱 첫 화면에 나옵니다 (예: 192.168.x.x). 카메라 주소는 서버 설정에만 있고 브라우저에는 노출되지 않습니다.

3한 번에 실행하기

1
WSL 이미지를 만들고 5개 서비스를 켭니다. 처음 한 번은 10~20분 걸립니다 (PyTorch·YOLO 등 다운로드). 두 번째부터는 몇 초입니다. 
docker compose up --build -d
2
WSL 상태를 확인합니다. fastapi가 healthy가 될 때까지 1분쯤 걸릴 수 있습니다 (AI 모델 로딩). 
docker compose ps
정상 상태django · celery · fastapi · postgres · redis 5개 모두 running, fastapi · postgres · redis 는 healthy
DB 테이블 만들기(마이그레이션)는 django 컨테이너가 켜질 때 자동으로 실행됩니다. 직접 하려면: docker compose exec django python manage.py migrate

10문제가 생겼을 때

브라우저에서 접속이 안 되거나 다른 화면(404)이 뜬다

8000번을 다른 프로그램이 쓰고 있는 경우입니다. 확인: Windows netstat -ano | findstr :8000
.env에서 DJANGO_PORT=8010, DJANGO_CSRF_TRUSTED_ORIGINS=http://localhost:8010,http://127.0.0.1:8010 로 바꾸고 docker compose up -d → http://localhost:8010.

로그인·분석 시작 때 "CSRF 검증 실패" (403)

포트를 바꿨는데 DJANGO_CSRF_TRUSTED_ORIGINS를 안 바꾼 경우입니다. 접속 주소와 같은 포트로 맞추고 docker compose up -d.

WSL에서 docker: command not found

Docker Desktop → Settings → Resources → WSL integration → Ubuntu 켜기 → Apply & restart, 터미널 다시 열기.

Docker Desktop이 오류창을 띄우며 시작이 안 된다

"Reset to factory defaults"는 누르지 마세요 (모든 이미지와 DB가 지워집니다). 먼저 Docker Desktop을 완전히 종료 → 다시 실행해 보고, 그래도 안 되면 PC 재부팅. 재부팅 직후 docker-secrets-engine 관련 오류라면 %LOCALAPPDATA%\docker-secrets-engine 폴더 이름을 바꾼 뒤(예: 뒤에 .old) Docker Desktop을 다시 켜면 새로 만들어집니다.

django가 계속 restarting, 로그에 password authentication failed

DB(볼륨)를 만들 때의 비밀번호와 지금 .env의 비밀번호가 다른 경우입니다. 데이터를 지키며 맞추기:

set -a; . ./.env; set +a
docker compose exec postgres psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "ALTER USER \"$POSTGRES_USER\" WITH PASSWORD '$POSTGRES_PASSWORD';"
docker compose restart django celery

데이터가 필요 없다면 docker compose down -v 후 다시 up --build -d.

fastapi가 unhealthy / 분석이 "AI 서버에 연결할 수 없습니다"로 실패

켠 직후 1분은 모델 로딩 중입니다. 계속되면 docker compose logs fastapi 로 원인을 확인하고 http://localhost:8001/health의 error를 봅니다.

IP Webcam: "카메라에 연결할 수 없습니다"

휴대폰 앱이 켜져 있고 화면이 켜져 있는지, PC와 같은 와이파이인지, .env 주소의 IP·포트가 앱에 표시된 것과 같은지 확인합니다. 확인: WSL curl -s -o /dev/null -m 3 -w "%{http_code}\n" http://<폰IP>:4747/video → 200

IP Webcam: "카메라가 다른 곳에서 사용 중입니다"

DroidCam은 연결을 하나만 받습니다. 다른 브라우저 탭·PC에서 DroidCam 화면을 닫고, 진행 중인 분석이 끝난 뒤 다시 시도합니다.

IP Webcam 결과가 이상하다 (사람이 여러 명, 신뢰도가 매우 낮음)

영상이 옆으로 누워 있을 가능성이 큽니다. 결과 화면의 Skeleton Overlay를 보고 누워 있으면 .env에 CAMERA_ROTATE=90(또는 270) → docker compose up -d. 전신이 화면에 들어오게, 한 사람만 나오게 찍습니다.

신뢰도가 60%대에서 더 올라가지 않는다

정상입니다. 기본 모델은 동작마다 학습 영상이 1개뿐이라 데이터가 부족해 60~70%대가 한계입니다 (README "알려진 한계" 참고). 숫자를 부풀리지 않고 그대로 보여 줍니다.
